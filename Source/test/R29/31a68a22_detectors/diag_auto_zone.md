# Диагностическая записка: Автозонирование в FDSE vs FDS6
**Дата:** 2026-10-21
**Кейс:** 31a68a22_detectors
**Статус:** Анализ завершен. Реализация автозонирования в FDSE не рекомендуется.

## 1. Текущее состояние в FDSE (fds5ng)
- **Механизм:** Только ручное задание зон через `&ZONE XB=...` или автоматическое создание одной зоны для полностью герметичных помещений (`SEALED=.TRUE. .AND. N_ZONE==0`).
- **MINIMUM_ZONE_VOLUME:** Параметр читается из `&MISC` (read.f90:1357), но **игнорируется** в логике. Комментарий в коде: "R29b: читается и игнорируется (FDS6)".
- **PRESSURE_ZONE:** Массив `PRESSURE_ZONE(I,J,K)` назначается на этапе инициализации на основе `&ZONE XB`. Динамического пересчета/разбиения зон в процессе расчета нет.
- **N_ZONE:** Фиксируется при чтении входного файла и не меняется в runtime.

## 2. Сравнение с FDS6
- В FDS6 реализован алгоритм автоматического определения связанных объемов (pressure zones) на основе геометрии и открытых проемов.
- Для кейса `31a68a22_detectors`: FDS6 создал **17 зон**, FDSE — **1 зону**.
- Разница в количестве зон приводит к различиям в расчете давления и газообмена между помещениями.

## 3. Оценка необходимости реализации в FDSE
### Аргументы ЗА:
- Улучшение точности расчета давления в многокомнатных зданиях без ручного задания `&ZONE`.
- Совместимость с входными файлами FDS6, где пользователь ожидает автоматического поведения.

### Аргументы ПРОТИВ:
- **Сложность:** Алгоритм поиска связанных объемов требует обхода графа смежности ячеек/помещений, что нетривиально для структурированных сеток FDS.
- **Производительность:** Динамическое определение зон на каждом шаге (или даже при рестарте) добавляет накладные расходы. В FDS6 это делается один раз при инициализации, но для сложных геометрий может быть дорого.
- **Риск нестабильности:** Изменение топологии зон в процессе расчета (если двери открываются/закрываются) может вызвать скачки давления и численную неустойчивость.
- **Низкий приоритет:** Для большинства инженерных задач ручное задание `&ZONE` достаточно. Пользователи Fenix+ уже задают зоны явно через GUI.

## 4. Выводы и рекомендации
1. **Не реализовывать** полноценное автозонирование в FDSE на данном этапе. Риск внесения регрессий превышает пользу.
2. **Документировать** различие в поведении: если в FDS6-файле нет `&ZONE`, FDSE создаст одну глобальную зону (для sealed) или потребует явного указания (для unsealed).
3. **Опционально:** реализовать упрощенный вариант — автоматическое создание зон по `&MESH` границам (каждый mesh = отдельная зона), если `N_ZONE==0`. Это дешево и покрывает 80% случаев многосеточных расчетов.
4. **MINIMUM_ZONE_VOLUME:** Оставить как есть (ignored). Его использование имеет смысл только при наличии алгоритма динамического дробления зон.

## 5. Влияние на физику/скорость (теоретическая оценка)
| Аспект | Без автозонирования (FDSE сейчас) | С автозонированием (как FDS6) |
|---|---|---|
| Точность давления | Ниже в сложных геометриях | Выше |
| Скорость инициализации | Быстрее | Медленнее (обход графа) |
| Скорость расчета | Без изменений | +5-15% overhead (доп. массивы, индексы) |
| Стабильность | Высокая | Риск скачков при изменении топологии |
| Удобство пользователя | Требует ручного &ZONE | Прозрачно для FDS6-файлов |
